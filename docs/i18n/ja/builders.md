# OpenRoot builder として参加する

何を作るかは自分で決めます。合法で、安全にホストでき、他者の権利と公開済みの参加グループ要件を守るソフトウェアなら、どの分野でも検討できます。

自分のアイデアを持ち込めます。プログラミング言語、リポジトリや文書の言語は自由で、英語以外も歓迎します。技術構成、範囲、ロードマップ、方向性は自分で決めます。英語や AI のみに限定された集合ではありません。

開発中はリポジトリを非公開にできます。資金付きグループに参加する前に、期間と公開要件を合意します。恣意的な期限や自動公開はありません。公開リリースや利用実績が条件のマイルストーンには、合意した証拠が必要です。他の builders は非公開コードに自動アクセスできませんが、Organization の所有者は管理権限を保持します。

## 申請とアクセス

申請では、メールアドレスと正確な GitHub ユーザー名を求めます。OpenRoot の承認が必要です。誰でもポータルに登録できるわけではなく、Google やメールでログインしても承認を省略できません。

GitHub アカウントが前提です。承認後、Organization の招待を受け入れ、その中で開発します。https://openroot.dev/apply で手動審査用の申請を受け付けます。送信だけでアカウント作成やアクセス付与は行われません。追加アカウント、GitHub Apps、プロジェクトチームの審査を申請できます。パスワード、トークン、秘密鍵は送らないでください。

承認すると、参加手続きが未完了のポータルアカウントを作成し、案内メールを送ります。承認されたメールアドレスで https://openroot.dev/portal にログインし、届いたコードはそのページだけに入力してください。Kristofer はポータルアカウントを承認する前に GitHub Organization の招待を手動で送ります。承認後、招待の承認と Organization 内でのリポジトリ作成手順をまとめた歓迎メールを1通だけ送ります。GitHub 身元の自動連携、プロジェクト指標、正式参加、報酬請求はまだ利用できません。未完了アカウントの期限は申請時の90日間から延長されません。承認だけで資金が確保された報酬を得られるわけではありません。

## プロジェクトを決める前の申請

まだ決めていない場合は「何を作るかまだ決まっていません」にチェックしてください。関心のメモは任意で、提案やリポジトリ URL を無理に作る必要はありません。これは手動審査用の未決定申請で、承認済みプロジェクトや報酬付きグループではありません。報酬資格には具体的なプロジェクトとマイルストーン条件の承認が必要です。

## 申請条件と公開済みポリシー

送信前に現在の[申請条件](https://openroot.dev/apply#application-terms)と公開済みの builder・[報酬ポリシー](rewards.md)を明示的に承諾してください。プライバシー同意とは別です。バックエンドは現在の条件バージョン **2026-10-12-1** と送信時刻を要求・記録します。未チェック、欠落、旧バージョンの承諾は拒否します。

申請ルール：

- 正確な情報と共有許可のある資料のみ提出してください。認証情報、非公開コード、機微な個人情報は含めないでください。
- 申請は手動審査の依頼であり、アカウント作成、Organization 加入、リポジトリ権限、報酬の約束ではありません。プロジェクト未決定でも申請できます。
- 送信でプロジェクト、コードの権利、リポジトリは移転しません。その後承認されるプロジェクトは他者の権利と公開ポリシーを守る必要があります。
- 承認、アクセス、マイルストーン、報酬の提供可能性、移転は別の審査と合意条件が必要です。登録だけで報酬資格は得られません。
- 参加、プロジェクト・離脱、資金付き報酬の合意は別です。申請によって未公開の将来条件や未発表の目標を承諾することはありません。

プライバシー、保存期間、訂正・削除依頼は下記をご覧ください。問い合わせ先：hello@openroot.dev。

## 申請のプライバシー

Kristofer Jussmann が運営する OpenRoot は、メール、正確な GitHub ユーザー名、提案、任意の証拠、共同開発・アクセスの希望、紹介情報、任意の認知経路、同意記録を審査と関連連絡のために収集します。申請者が任意で回答する認知経路は、どこで OpenRoot を知ったかを把握するために使用し、追跡 Cookie は使いません。認証情報、非公開コード、機微な個人情報は送らないでください。他のアカウントを記載する場合は許可を得てください。

申請はフィンランドの Google Cloud に非公開で保存し、許可された管理者のみアクセスできます。記録は 90 日後に期限切れとなる予定で、自動削除は非同期です。承認されたポータルアカウントには有効化前に別の条件を設けます。基盤は技術的リクエストログを処理しますが、申請サービスは申請内容を意図的にログに記録しません。

申請してもニュースレターに登録されません。閲覧、訂正、削除、同意撤回は hello@openroot.dev へ連絡してください。対応前に本人確認が必要な場合があります。送信は記載したメールや GitHub アカウントを管理している証明にはなりません。

## 役割

Builders は開発、ユーザー獲得、保守、マイルストーンの証拠提出を担当します。OpenRoot は刊行物や SNS で可能な限り、完全無料で紹介します。すべての宣伝活動を運営するわけではなく、掲載、リーチ、好意的な評価、成功を保証しません。

プロジェクトの宣伝は1回の紹介に限定されません。ニュースレターや SNS で、プロジェクトの注目ポイント、作品紹介、詳しい解説記事として複数回取り上げられる場合があります。Builders はリリース、大きな更新、ユーザーの活用事例を hello@openroot.dev に送り、編集側での検討を依頼できます。この支援は完全無料で、報酬の獲得や交換は必要ありません。時期と形式は編集上の適合性と対応可能な範囲によって決まります。OpenRoot は再掲載、リーチ、成果を保証しません。

OpenRoot は、他の人が使うことを目的としたプロジェクトを開発、または検討している builders を求めています。問題を解決するソフトウェア、便利なツール、ユーザーが何かを実現するためのソフトウェアなどが対象です。ソフトウェアの分野、プログラミング言語、ドキュメントの言語は問いません。既存ユーザーは必要ありません。まだアイデアが決まっていない申請者や、合意した非公開の開発期間も歓迎します。

参加を準備している方や、ハッカソンのプロジェクトを継続している方も歓迎します。対象として事前承認されたハッカソンでの優れた成果に対する追加報酬を計画しています。対象イベント、成果、証拠、資金、ボーナス条件は、報酬付きの募集を始める前に公開し、合意する必要があります。優勝しても OpenRoot のポイントや報酬が自動で付与されるわけではありません。具体的な対象ハッカソンやボーナス額はまだ公表しておらず、報酬請求もまだ利用できません。

参加は排他的ではありません。ハッカソンや外部共同開発、その他の活動に参加できます。イベント規則、ライセンス、貢献者への義務を確認してください。OpenRoot 参加のためにそうした機会を放棄する必要はありません。

GitHub のチームとリポジトリロールで共同作業の範囲を限定します。プロジェクトのアクセス権は Organization 全体の管理権ではありません。将来のポータルは関連リポジトリやチームプロジェクトを表示します。作成者が唯一の貢献者・報酬受取人になるとは限りません。

## プロジェクトはあなたのもの

予定の方針では、自分のコードの権利を保持し、プロジェクトを主導します。リポジトリは OpenRoot Organization 内にホストされ、承認された責任者にリポジトリ単位の Admin を付与します。Organization の所有者は管理アクセスを保持します。Admin は GitHub の名前空間の個人所有を意味しません。ライセンス、離脱、移転条件は参加前に合意します。

## 既存プロジェクトと共同開発

ユーザー、ダウンロード、スターがある既存リポジトリも提案できます。URL と日付付き証拠を先に提出し、審査前に移転しないでください。メンバー承認、移転、参加、報酬請求は別々の手動判断です。既存指標は合意した基準値とグループ規則に従ってのみ評価し、Organization に入っただけでは資格になりません。

プロジェクト専用チームは複数の承認済みリポジトリを扱えます。責任者は限定範囲の Admin、共同開発者は審査済みロールを持ちます。全体への書き込み権限や親チームからの意図しない継承を避けます。自動化アカウントは独立した受賞 builder と数えません。

## 参加前

権利、ライセンス、保守責任、離脱・移転、チーム報酬の配分を開示して合意する必要があります。最終契約は準備中です。Organization への加入だけでは解決しません。

参加グループは報酬、定員、閾値、測定期間、審査ルールを示す必要があります。決まる前に興味を示しても報酬の権利は生じません。

[仕組み](how-it-works.md)と[報酬](rewards.md)をご覧ください。

## 紹介

予定の[紹介プログラム](referrals.md)は、承認後に検証済みマイルストーンを達成した builders の紹介を評価します。登録件数への報酬ではありません。申請者は紹介者の正確な GitHub 名を記入できます。開始前に資金と最終条件を公開します。

## 未完了ポータルアカウントのプライバシー

審査による承認後、メールアドレス、GitHub ユーザー名、参加手続きの状態を含む未完了のポータルアカウントを作成します。申請時の有効期限を引き継ぎ、90日間の保存期間は延長しません。ログインには必要な安全なブラウザーセッション Cookie を使用し、8時間後に期限切れになります。メールコードの認証要求は10分後に期限切れとなり、サービスは平文コードではなくハッシュを保存します。Google Cloud は非公開のアカウント・審査記録を処理し、Resend はログイン・承認のトランザクションメールを処理します。申請を審査できるのは許可された管理者だけで、builders は自分のポータル情報だけにアクセスできます。ニュースレター登録、広告追跡、GitHub の自動招待は行いません。正式参加と有効なプロフィールの保存には別の条件が必要です。開示、訂正、削除については hello@openroot.dev にご連絡ください。

## 既存プロジェクト：手順

**承認された既存プロジェクトは OpenRootdev 内でホストする必要があります。** プロジェクト審査後、元のリポジトリを移管するか、新しい組織リポジトリにコードをコピーします。組織外のリポジトリのリンクだけでは不十分です。既存プロジェクトでは、上の新規作成手順の代わりに以下を使ってください。

**どちらの方法でも事前に：** 元の URL を提出し、移管・コピー権限と貢献者/ライセンスの権利を確認し、OpenRoot と移行方法を合意して組織招待を受諾します。バックアップし、移管や push 前にシークレット、連携、Actions の料金を確認してください。承認や権限が不明なら hello@openroot.dev へ。

### 方法 A：元のリポジトリを移管

スター、issue、pull request、Git 履歴を保ちたい場合に推奨します。

- **1.** GitHub で元のリポジトリを開き、**Settings → General → Danger Zone → Transfer** へ進みます。リポジトリ Admin と OpenRootdev での作成権限が必要です。他の組織からの移管にはその所有者の対応が必要な場合があります。
- **2.** 新しい所有者を **OpenRootdev** に設定します。名前が空いていることと GitHub の警告（非公開リポジトリは GitHub Free で有料機能を失う場合があります）を確認し、リポジトリ名を入力して確定します。
- **3.** URL が `https://github.com/OpenRootdev/` で始まることを確認します。リポジトリ単位の Admin とチームアクセスを OpenRoot に確認してもらってください。組織所有者の管理権限は残ります。
- **4.** 既存の各ローカルクローンで `git remote set-url origin https://github.com/OpenRootdev/YOUR-REPOSITORY.git` を実行します。作業再開前に連携、デプロイ、Pages、シークレット、workflow を確認してください。旧パスでリポジトリを再作成するとリダイレクトが壊れる場合があります。

### 方法 B：新しい組織リポジトリにコードをコピー

元のリポジトリをその場所に残し、承認されたコピーを OpenRootdev で開発したい場合に使います。

- **1.** [New repository](https://github.com/new?owner=OpenRootdev) を開きます。**Owner = OpenRootdev**、合意した名前、公開/非公開を確認します。README、license、.gitignore は**初期化せず**、空のリポジトリを作ります。
- **2.** ターミナルで例の名前を置き換え、新しいローカルフォルダーを使います：`git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git openroot-project`、続けて `cd openroot-project`。
- **3.** 元の remote を変えずに宛先を追加します：`git remote add openroot https://github.com/OpenRootdev/YOUR-REPOSITORY.git`。
- **4.** 現在のブランチを push します：`git push openroot HEAD:main`。組織リポジトリにファイルがあることを確認します。以後は元の `origin` ではなく `openroot` に push してください。宛先が空でない、または拒否された場合は停止して相談し、強制 push しないでください。
- **5.** コピーされるのは選択したブランチから到達できるコミット履歴です。**スター、issue、pull request、release、設定、全ブランチ/タグはコピーされません。** Git LFS オブジェクトとサブモジュールは別途対応が必要なので相談してください。ライセンス/帰属表示ファイルを保持し、シークレットをコピーしないでください。

審査済みプロジェクトに関連付けるため、最終的な組織リポジトリ URL を OpenRoot に送ってください。既存の利用実績と報酬には合意した基準と別途承認が必要で、コピー間で重複計上しません。参加のためだけに元のリポジトリを削除する必要はありません。自分のコードの権利は保持しますが、組織所有者の管理アクセスはなくなりません。

公式参考：[移管](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository)、[新規リポジトリ](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)、[Git push](https://git-scm.com/docs/git-push)。
