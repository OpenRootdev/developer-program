# Hitos y recompensas

Las recompensas ayudan a seguir construyendo. Son beneficios no monetarios aportados mediante colaboraciones confirmadas o una cohorte financiada explícitamente.

## ¿Qué se recompensa?

Cada proyecto usa una vía apropiada:

- Atención: estrellas GitHub orgánicas, interés externo significativo o cobertura.
- Distribución: descargas de versiones/paquetes, clones completos o descargas de imágenes de contenedores durante un periodo definido.
- Adopción: usuarios activos o recurrentes, o proyectos independientes que integran el software.
- Uso sostenido: una medida relevante de adopción mantenida en el tiempo.

Las estrellas indican interés; las descargas, distribución. Ninguna demuestra automáticamente usuarios activos. Automatización repetida, interacción comprada o inflación propia no prueban resultados reales. Cada cohorte publicará las exclusiones exactas.

Los umbrales numéricos no están finalizados. Cada proyecto debe conocer métrica, fuente, referencia, umbral, periodo, pruebas, revisión, recompensa y límite de solicitudes.

## ¿Qué beneficios?

Categorías: acceso IA/API, GPU/cloud, suscripciones, IDE y herramientas útiles. Los builders deben poder elegir entre opciones elegibles y disponibles.

## Elegir y usar una recompensa

Tras aprobarse el hito y la solicitud, los builders eligen entre opciones elegibles y disponibles para su proyecto o cohorte. Importe, modelos y condiciones se confirman para cada oferta; EUR 50-1,000 no implica conceder automáticamente el máximo a cada builder. La promoción totalmente gratuita, dentro de lo posible, es un beneficio separado y no consume la recompensa.

Hermes, OpenClaw y OpenCode admiten proveedores personalizados o endpoints compatibles con OpenAI, pero el gateway real de las recompensas aún no se ha probado con estos clientes. El chat de Cursor con clave propia requiere verificar cliente/modelo/gateway; los créditos no incluyen suscripción a Cursor ni Tab. Codex necesita Responses API, streaming y conversaciones con llamadas a herramientas. Claude Code necesita un formato de API de gateway admitido, como Anthropic Messages. La compatibilidad solo con OpenAI Chat Completions no demuestra soporte para Codex o Claude Code. Endpoint, IDs de modelos, límites de clientes y condiciones de privacidad del destinatario se confirman antes del canje.

Consulta los [requisitos de gateway de Codex](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility) y los [requisitos de gateway de Claude Code](https://code.claude.com/docs/en/llm-gateway-protocol). Este borrador no promete compatibilidad de extremo a extremo.

## Financiación y equidad

Recompensas y financiación se confirman antes de inscribirse en una cohorte con beneficios. Una lista de interés no financiada no promete recompensas. Si el inventario es limitado, capacidad y reservas deben ser visibles desde el principio.

Distingue recompensas garantizadas a solicitudes válidas de premios juzgados o limitados por cuotas. Los requisitos no pueden cambiar retroactivamente para rechazar una solicitud válida. Referencias de proyectos existentes y aceptación de logros pasados se definen antes de inscribirse.

Los beneficios se asignan según el acuerdo de proyecto/equipo, no se multiplican automáticamente por contribuidor. Los pedidos pasan por envío, revisión, aprobación y emisión. El canje puede ser desconocido si el proveedor no lo confirma. Se puede pedir corrección o revisión.

Los beneficios no monetarios también requieren contabilidad y revisión por jurisdicción antes del lanzamiento. Este borrador no determina su tratamiento fiscal.
