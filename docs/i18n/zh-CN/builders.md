# 加入成为 OpenRoot builder

你决定开发什么。任何软件类别都可以考虑，但须合法、适合安全托管、尊重他人权利，并符合该批次公开要求。

欢迎自带想法。编程语言、仓库及文档语言均不限，包括非英语仓库。技术栈、范围、路线图和方向由你选择；计划并非仅限英语或 AI 项目。

仓库可在开发阶段保持私有。加入有资金支持的批次前，约定私有期及公开发布要求。不设置任意倒计时，也不自动公开仓库。依赖公开发布或采用情况的里程碑仍须提供约定证据。其他 builders 不会自动获得你的私有代码访问权。

## 申请与访问

申请需填写邮箱和准确的 GitHub 用户名。必须获得 OpenRoot 批准。门户不允许所有人直接注册；使用 Google 或邮箱登录不能绕过批准。

需要 GitHub 账号。获批 builders 接受 OpenRootdev 邀请，并在组织内创建仓库。请在 https://openroot.dev/apply 申请成员资格人工审核；提交不会创建账号或授予访问权。加入后，普通仓库协作由你自行管理。组织级应用或设置需要协助时，请联系 OpenRoot。不要提交密码、令牌或私钥。

批准后会创建待完成加入流程的门户账号，并发送说明邮件。请使用获批邮箱登录 https://openroot.dev/portal，只在该页面输入邮件中的验证码。Kristofer 会在批准门户账号之前手动发送 GitHub 组织邀请。批准后只发送一封欢迎邮件，说明接受邀请和在组织中创建仓库的步骤。自动 GitHub 身份关联、项目指标、门户自动奖励领取尚不可用。待完成加入流程的账号沿用申请原定的 90 天有效期。批准本身不代表获得有资金保障的奖励。

## 尚未选定项目时申请

如果尚未决定项目，可勾选“我还不确定要开发什么”。兴趣说明可留空，无须编造提案或仓库 URL。这是供人工审核的未定项目申请，不是已批准项目或有奖励的批次。获得奖励资格前，仍须批准具体项目及里程碑条款。

## 申请条款与已发布政策

提交前，须明确接受当前[申请条款](https://openroot.dev/apply#application-terms)及已发布的 builder 与[奖励政策](rewards.md)。这与隐私同意分开。后端要求并记录当前条款版本 **2026-10-24-1** 和提交时间；未勾选、缺失或旧版本同意会被拒绝。

申请规则：

- 提供真实信息，只分享获准分享的材料。不要提供凭据、私有源代码或敏感个人信息。
- 申请仅请求成员资格人工审核，不创建账号、授予组织访问权或承诺奖励。未选定项目也可以申请。
- 申请不会转移项目、代码权利或仓库。项目须尊重他人权利并遵守已发布的计划政策。
- 加入后，成员无需再次向 OpenRoot 申请即可创建新仓库及管理仓库协作者。从零创建的新仓库自动加入计划，并须遵守政策。已有项目的迁移仍需审核和约定。
- 奖励资格、基线、资金限额及领取仍需单独约定和审核。申请不表示接受未发布的未来条款，也不保证奖励。

隐私、保留期及更正/删除请求见下文。问题请联系 hello@openroot.dev。

## 申请隐私

OpenRoot 由 Kristofer Jussmann 运营，收集邮箱、准确 GitHub 用户名、项目提案、可选证据、协作/访问请求、推荐信息、可选的发现渠道及同意记录，用于审核申请和相关沟通。申请人可自行选择是否说明如何得知 OpenRoot；此信息用于了解开发者从哪里找到我们，不使用跟踪 Cookie。不要提供凭据、私有源代码或敏感个人信息；列出其他账号前须获得其许可。

申请私密存储在芬兰的 Google Cloud，仅授权管理员可访问。记录计划在 90 天后过期；自动删除是异步的。获批门户账号启用前会有单独条款。托管基础设施处理技术请求日志，申请服务不主动记录申请内容。

申请不会订阅通讯。联系 hello@openroot.dev 可请求访问、更正、删除申请或撤回同意；处理前可能需要身份验证。提交不能证明你控制所填写的邮箱或 GitHub 账号。

## 你的职责

Builders 负责开发、吸引用户、维护项目并提供里程碑证据。OpenRoot 会尽力通过刊物和社交媒体宣传成员项目，完全免费，但不负责每个项目的全部营销，也不保证报道、传播范围、正面评价或成功。

项目宣传不局限于一次介绍。项目可以通过项目亮点、成果展示和深度文章，在通讯和社交媒体中多次获得介绍。Builders 可以将新版本、重要更新和用户故事发送至 hello@openroot.dev，供编辑评估。这项支持完全免费，无需先获得或兑换奖励。发布时间和形式取决于编辑适配性和可用资源；OpenRoot 不保证重复报道、传播范围或结果。

如需建议介绍某个项目，请发送邮件至 hello@openroot.dev，提供项目或版本链接、受益人群、更新内容、希望重点介绍的具体要点，以及有权分享的可选截图或演示。OpenRoot 会人工撰写最终帖子，使其符合自身的编辑标准和各平台的风格。无需先提交请求：OpenRoot 也可能主动介绍成员项目的公开更新。请勿发送凭据、机密材料或他人的个人数据。目前采用邮件流程，尚无专用的门户申请表。

我们希望加入的 builders 正在创建或探索供他人使用的项目：能够解决问题、提供实用工具或帮助用户完成任务的软件。欢迎任何软件类别、编程语言和文档语言。项目无需已有用户；尚未确定项目的申请者，以及经约定的私有开发阶段，仍然受到欢迎。

我们也欢迎准备参加黑客松或继续开发黑客松项目的 builders。我们计划为符合条件且事先获批的黑客松中的优秀表现提供额外奖励。符合条件的活动、成果、证据、资金和额外奖励条款，必须在有奖励的方案启动前公布并约定。获胜不会自动获得 OpenRoot 积分或奖励。目前尚未公布具体符合条件的黑客松或额外奖励金额；黑客松额外奖励领取尚未开放。

参与不排他。可以参加黑客松、外部合作或其他活动。请检查活动规则、贡献者和许可义务；加入 OpenRoot 不要求放弃这些机会。

现有组织成员无需再次申请或另行获得 OpenRoot 批准即可创建新仓库。从零创建的新仓库会自动加入计划，并须遵守计划政策。OpenRoot 会人工审核仓库；如需修改或移除，会联系仓库管理员。随着组织发展，计划引入政策检查机器人，目前尚未启用。加入计划不等于奖励获批：私有项目须先公开，并满足约定的里程碑和资金条件，才能获得奖励。

## 项目仍属于你

你保留自己代码的权利，并主导项目。仓库托管在 OpenRootdev 下，创建仓库或通过获批转移带入仓库的成员拥有仓库级 Admin 权限。这不是雇佣开发，也不要求整体转让代码权利。

## 已有项目与协作

可以提交已有用户、下载量或星标的仓库。先提供 URL 和带日期的证据，审核前不要转移。成员批准、仓库转移、加入奖励批次和奖励申请是分别进行的人工决定。现有数据仅按约定基线与批次规则计算，不会因仓库进入组织而自动合格。

仓库管理员自行决定协作者、项目团队、仓库角色及贡献规则，无需另行获得 OpenRoot 批准。一个项目可以使用多个仓库。其他成员不会自动获得私有代码访问权或仓库写权限。仓库范围的应用遵循 GitHub 的正常权限控制；组织级设置可能需要 OpenRoot 协助。

## 许可与奖励细节

选择合适的项目许可证，尊重已有许可、署名及贡献者权利。许可及项目奖励细节可在提交时记录，或在需要时直接约定。无需另签维护者权利或贡献规则协议；贡献规则由仓库管理员制定。

加入的批次必须说明奖励、容量、门槛、统计周期和审核规则。条款确定前，表达兴趣不会产生领奖权。

参阅[运作方式](how-it-works.md)和[奖励规则](rewards.md)。

## 待完成加入流程的门户隐私

审核批准后会创建待完成加入流程的门户账号，包含邮箱、GitHub 用户名和加入状态。该账号沿用申请原定到期时间，不延长 90 天保留期限。登录使用必要的安全浏览器会话 Cookie，八小时后到期。邮件验证码请求十分钟后到期；服务保存验证码哈希值，不保存明文验证码。Google Cloud 处理私有账号及审核记录；Resend 处理事务性登录和批准邮件。只有获授权管理员可以审核申请，builders 只能访问自己的门户信息。不会自动订阅新闻邮件、进行广告追踪或发送 GitHub 邀请。完整加入流程和活跃资料保留需要另行约定。访问、更正或删除请求请联系 hello@openroot.dev。

## 已有项目：分步操作

**获批的已有项目必须托管在 OpenRootdev 下。** 项目审核后，可以转移原仓库，或将代码复制到新的组织仓库。仅提供组织外仓库的链接不够。已有项目应按以下步骤操作，而不是上面的新项目创建步骤。

**两种方式都需先完成：** 提交原 URL，确认转移或复制权限及贡献者/许可权利，与 OpenRoot 约定迁移方式，并接受组织邀请。备份项目，在转移或推送前检查秘密、集成和 Actions 费用。审批或权限不明确时联系 hello@openroot.dev。

### 方式 A：转移原仓库

希望保留星标、议题、拉取请求和 Git 历史时，建议选择此方式。

- **1.** 在 GitHub 打开原仓库，进入 **Settings → General → Danger Zone → Transfer**。你需要仓库 Admin 和在 OpenRootdev 创建仓库的权限；从其他组织转出可能需要该组织所有者参与。
- **2.** 将新所有者设为 **OpenRootdev**。确认目标名称未被占用，阅读 GitHub 警告（私有仓库转入 GitHub Free 后可能失去付费计划功能），输入仓库名称并确认。
- **3.** 确认仓库 URL 以 `https://github.com/OpenRootdev/` 开头，并在 Settings 中核实自己的仓库 Admin 权限。如缺少预期权限，请联系 hello@openroot.dev。
- **4.** 在每个已有本地克隆中运行 `git remote set-url origin https://github.com/OpenRootdev/YOUR-REPOSITORY.git`。恢复工作前检查集成、部署、Pages、秘密和工作流。不要重新创建旧仓库路径，以免破坏重定向。

### 方式 B：将代码复制到新的组织仓库

如果希望保留原仓库的位置，并在 OpenRootdev 维护获批项目的副本，可选择此方式。

- **1.** 打开 [New repository](https://github.com/new?owner=OpenRootdev)。核实 **Owner = OpenRootdev**，选择约定名称及公开/私有可见性。**不要初始化** README、license 或 .gitignore；创建空仓库。
- **2.** 在终端替换示例名称，使用新的本地文件夹：`git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git openroot-project`，然后 `cd openroot-project`。
- **3.** 添加目标而不改变原远程：`git remote add openroot https://github.com/OpenRootdev/YOUR-REPOSITORY.git`。
- **4.** 推送当前检出的分支：`git push openroot HEAD:main`。确认文件出现在组织仓库。后续更新推送到 `openroot`，而非原来的 `origin`。若目标不是空仓库或推送被拒绝，请停止并求助，不要强制推送。
- **5.** 此操作复制所选分支可达的提交历史，**不复制星标、议题、拉取请求、发布记录、仓库设置或所有分支/标签**。Git LFS 对象和子模块需要单独处理，请求帮助。保留许可/署名文件，不要复制秘密。

将最终组织仓库 URL 发给 OpenRoot，以关联审核过的项目。已有采用数据及奖励仍需约定基线和单独批准，副本之间不得重复计数。无需为参与计划删除原仓库。你保留自己代码的权利。

官方参考：[转移](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository)、[新建仓库](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)、[Git push](https://git-scm.com/docs/git-push)。
